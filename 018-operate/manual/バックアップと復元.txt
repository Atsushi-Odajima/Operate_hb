Operate 説明書　バックアップと復元
==================================================

このファイルは、Operate のデータの控え（バックアップ）を取る方法と、
万一のときにデータを元に戻す（復元）方法を説明します。

・バックアップの作成と検証 …… オーナーが画面から行えます
・復元 …………………………… サーバー管理者（販売者・導入担当者）がコマンドで行います


■ バックアップに含まれるもの

その組織のすべてのデータを、1 つのファイル（.json.gz 形式）にまとめます。

・文書と、すべての版・承認・レビュー・コメント
・研修・テスト・受講記録・完了証・オンボーディング
・確認記録
・操作ログ（監査ログ）
・添付ファイル・画像
・ユーザー・部署・役割・設定
・ハッシュ化されたパスワード（元のパスワードには戻せない形式）

重要：ファイルには機密・極秘の文書やパスワード情報も含まれます。
必ず暗号化された安全な場所（アクセスできる人を限定した保管先）に保存してください。
メールやチャットで送らないでください。


■ バックアップを作る（オーナー）

1. メニュー「組織・ユーザー設定」→「バックアップ」タブを開きます。
2. 「バックアップを作成」を押します。
3. 「operate-backup-（組織ID）-（日付）.json.gz」がダウンロードされます。
4. 暗号化された保管先に移し、パソコンのダウンロードフォルダからは削除します。

・バックアップの作成は操作ログに記録されます。
・作成中も通常どおり使えます（その瞬間のデータをまとめて保存します）。


■ バックアップファイルを検証する（オーナー）

保管しているファイルが壊れていないか・書き換えられていないかを確認できます。

1. 「バックアップ」タブの「バックアップファイルの検証」でファイルを選びます。
2. 結果が表示されます。
　・「検証OK」または「検証NG」
　・組織名、作成日時
　・件数（文書／版／研修割当／監査ログ）
　・問題がある場合はその内容（例：チェックサムが一致しません）

チェックサムとは、データの中身から計算される確認用の値です。
作成時の値と一致しない場合は、ファイルの破損や改ざんの可能性があります。


■ おすすめの運用

・頻度：月 1 回以上、または大きな変更（大量の取り込み・組織変更）の前
・世代：過去数回分を残す（例：直近 3 か月分）
・確認：保管したら「検証」で OK になることを確認する
・データベース自体の自動バックアップ（ご利用のデータベースサービスの機能）も併用してください。
　Operate のバックアップは「組織単位の控え」、データベースの自動バックアップは
　「サーバー全体の控え」で、役割が異なります。


■ 復元する（サーバー管理者向け）

復元は、サーバーでコマンドを実行して行います。購入者の方は、販売者・導入担当者に依頼してください。

1. 事前確認（何も変更しません）
　npm run restore -- <バックアップファイル> --dry-run
　ファイルの検証結果と件数だけを表示します。

2. 空の環境に復元する（同じ組織がまだない場合）
　npm run restore -- <バックアップファイル>

3. 既存の組織を置き換える
　npm run restore -- <バックアップファイル> --replace
　同じ組織のデータを、バックアップの内容で置き換えます。
　現在のデータは失われるため、実行前に現在の状態のバックアップも取ってください。

※ コマンドは server フォルダで実行します。データベース管理用の接続設定（DATABASE_ADMIN_URL）が必要です。
※ サーバー側でバックアップを作るコマンド（npm run backup -- <組織ID> [出力ファイル]）もあります。

復元の安全対策
・復元の前にファイルを検証します（件数・チェックサム）。NG の場合は復元しません。
・復元は「全部成功するか、何も変えないか」のどちらかです。
　途中で失敗した場合は、データベースは復元前の状態のまま変わりません。
・復元後に、次の点を自動で確認します。問題があれば復元を取り消します。
　- 各データの件数がバックアップと一致しているか
　- 各文書の「現在の公開版」の指定が正しいか
　- 承認記録のハッシュ値が、承認時の内容と一致しているか
　- 研修の修了記録に対応する完了証があるか

復元後
・利用者は、もう一度ログインが必要になる場合があります。
・端末に保存していた文書は、次にオンラインになったとき自動で確認・更新されます。


■ 注意

・バックアップファイルを使えば、組織のすべてのデータを読み取れます。保管場所の管理を徹底してください。
・バックアップは組織ごとです。ほかの組織のデータは含まれません。
・サンプル組織（sample-works）のデータは、本番の組織と混ぜないでください。
