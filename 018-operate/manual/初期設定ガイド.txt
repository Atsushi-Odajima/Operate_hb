Operate 説明書　初期設定ガイド
==================================================

このファイルは、Operate を使い始めるときに「誰が・何を・どの順番で設定するか」を
まとめたものです。上から順に進めれば、最初のマニュアルを公開するところまで進められます。


■ 全体の流れ

　[販売者・導入担当者]  サーバーの準備 → 組織の作成 → オーナーの仮パスワードを渡す
　　　　　　↓
　[購入者（オーナー）]  初回ログイン → 部署・チーム → ユーザーと役割 → 承認できる範囲
　　　　　　　　　　　→ 文書の種類ごとのルール → 機密区分の扱い → AI を使うか決める
　　　　　　　　　　　→ 最初のマニュアルを作って公開


■ 1. 販売者・導入担当者が行うこと

次の作業はサーバーを扱う技術的な作業です。通常は販売者または導入を担当する方が行います。
（ご自身で運用する場合は、同梱の技術資料を参照してください）

・サーバー（Node.js 22）とデータベース（PostgreSQL 16。拡張機能 pgvector と pg_trgm が必要）の用意
・データベースの初期化（npm run migrate）
・通信の暗号化（https）とドメインの設定
・環境変数の設定（APP_SECRET、DATABASE_URL、PUBLIC_URL など）
・AI を「Anthropic Claude（外部サービス）」で使う場合は、サーバーに ANTHROPIC_API_KEY を設定
　（API キーはサーバーだけに置かれ、ブラウザには送られません）
・メール通知を使う場合のメール送信設定（「注意事項.txt」のメールの項を参照）
・組織の作成と、オーナーの登録
　npm run create-org -- <組織ID> <組織名> <オーナーのメールアドレス> <オーナーの氏名>
　を実行すると、オーナーの「仮パスワード」が表示されます。
・組織ID・メールアドレス・仮パスワードを、安全な方法で購入者のオーナーに伝える

※ 販売価格・契約条件・サポート範囲は販売者が定めます。


■ 2. 購入者（オーナー）が行うこと

▼ 2-1. 初回ログインとパスワード変更

1. ブラウザで Operate の URL を開きます。
2. 「組織ID」「メールアドレス」「パスワード（仮パスワード）」を入力して「ログイン」。
3. 左下の「アカウント」→「パスワードの変更」で、新しいパスワード（10 文字以上）に変更します。
　変更すると、ほかの端末でのログインは自動的に切れます。


▼ 2-2. 部署とチームを作る

メニュー「組織・ユーザー設定」→「部署・チーム」タブ

1. 「部署名（例：営業部）」と「コード（例：SALES）」を入れて「部署を追加」。
　コードは英数字・ハイフン・アンダーバーで 20 文字までです。文書番号などの目印に使います。
2. 部署の下の欄にチーム名を入れて「チームを追加」。
　チームは必要な場合だけで構いません（例：CS部 / 一次対応チーム）。

※ 部署・チームの作成は、オーナーとナレッジ管理者ができます。


▼ 2-3. ユーザーを登録し、役割を決める

メニュー「組織・ユーザー設定」→「ユーザー」タブ（オーナーのみ）

1. 「ユーザーを追加」を押します。
2. 名前・メールアドレスを入力します。
3. 「役割（複数可）」にチェックを入れます。
　オーナー／ナレッジ管理者／承認者／編集者／研修担当／メンバー／監査担当
　（役割の詳しい説明は「部署と権限.txt」）
4. 「所属（複数可）」で部署・チームを選びます。1 人が複数の部署に所属できます。
5. 入社日（任意）を入れます。新人オンボーディングの起算日の目安になります。
6. 「保存」を押すと「仮パスワード」が表示されます。
　この画面を閉じると再表示できません。本人に安全な方法で伝えてください。

・パスワードを忘れた人がいたら、同じ画面の「PW再発行」で仮パスワードを発行します。
・退職者は「無効化」します（詳しくは「部署と権限.txt」）。


▼ 2-4. 承認者の「承認できる範囲」を決める

ユーザーの編集画面で役割に「承認者」を付けると、「承認できる範囲」の欄が出ます。

・「全社」にチェック ……… どの部署の文書でも承認できます
・部署にチェック ………… チェックした部署の文書だけ承認できます

例）CS部長は「CS部」「EC運営部」、管理部長は「全社」。
※ オーナーとナレッジ管理者は、範囲の設定がなくてもすべての部署の文書を承認できます。
※ 作成者本人は、自分の文書を承認できません。


▼ 2-5. 文書の種類ごとのルールを決める

メニュー「組織・ユーザー設定」→「運用ルール」タブ（オーナーのみ）

「文書の種類ごとのルール」の表で、種類ごとに次を決めます。

・承認 …………………… 公開に承認が必要か
・承認の段数 …………… 1〜3 段
・方式 …………………… 「誰か1人」の承認で次へ ／ 「全員」の承認が必要
・定期レビュー ………… なし／30日／90日／180日／365日
・公開時の確認依頼 …… 公開したとき対象者に「読んで確認しました」を依頼するか

初期設定は次のとおりです。

　種類　　　　　　承認　　定期レビュー　公開時の確認依頼
　手順書（SOP）　 必要　　180日　　　　 しない
　社内規程　　　　必要　　365日　　　　 する
　ガイド　　　　　必要　　365日　　　　 しない
　FAQ　　　　　　 不要　　180日　　　　 しない
　チェックリスト　必要　　180日　　　　 しない
　テンプレート　　不要　　365日　　　　 しない
　参考資料　　　　不要　　365日　　　　 しない

※ AI が作成した下書きは、この設定に関わらず必ず承認が必要です。

同じ画面の「改訂・レビュー」では次も決められます。
・改訂時に「変更内容」の入力を必須にする（初期：必須）
・「まもなく期限」とする日数（初期：14 日）
・期限切れの文書の扱い
　「公開のまま、利用者に『確認中』の注意を表示」（初期）または「管理画面でのみ表示」
　※ 期限切れで自動的に非公開になることはありません。
・確認依頼の標準期限（初期：14 日）
・最後まで表示しないと「確認しました」を押せない（初期：オン）


▼ 2-6. 機密区分の扱いを決める

同じ「運用ルール」タブの「機密区分ごとの扱い」で、区分ごとに許可するかを決めます。

　区分　　　オフライン保存　PDF・添付のダウンロード　外部メンバーへの共有
　社内公開　許可　　　　　　許可　　　　　　　　　　許可
　社内限定　許可　　　　　　許可　　　　　　　　　　許可
　機密　　　不可　　　　　　許可　　　　　　　　　　不可
　極秘　　　不可　　　　　　不可　　　　　　　　　　不可（変更できません）
　（上は初期設定です）

「通知・検索分析」では次を決めます。
・メールでも通知する（件名とリンクのみ。本文は送りません）… 初期：オフ
・検索語を記録して分析する（利用者 ID とは紐づけません）…… 初期：オン
・検索語の保存期間 ………………………………………………… 初期：180 日

設定を変えたら、画面下の「保存」を押してください。


▼ 2-7. AI を使うか決める

メニュー「組織・ユーザー設定」→「AI設定」タブ（オーナーのみ）

新しく作った組織では、AI 機能は「オフ」になっています。オフのままでも、
検索・閲覧・研修など AI 以外の機能はすべて使えます。

使う場合は、先に「AI利用時の注意.txt」を読み、次を決めてください。
・「AI機能を使う」のオン／オフ、使う機能（AI検索／SOP下書き／テスト問題案）
・提供元：「社内処理のみ（外部送信なし）」または「Anthropic Claude（外部サービス）」
・AI に渡してよい機密区分（初期：社内公開・社内限定）
・利用量の上限（1 人あたり回数/分、組織全体の回数/日、月の予算上限 USD）

AI 設定の変更は、操作ログ（監査ログ）に記録されます。


▼ 2-8. 最初のマニュアルを作って公開する

1. メニュー「マニュアル」→「新しいマニュアル」。
2. 種類「手順書（SOP）」、タイトル、担当部署、機密区分、配布先を選びます。
3. テンプレート「標準SOP」を選んで「下書きを作成して編集する」。
4. 本文と「手順（ステップ）」を入力します（自動で保存されます）。
5. 「レビュー・承認に提出」→ 承認者を選んで「提出する」。
6. 承認者が「承認する」を押すと公開されます。

詳しくは「SOPの作り方.txt」「レビューと承認.txt」「公開と改訂.txt」を参照してください。

既存の Word・PDF のマニュアルがある場合は、「既存資料の取り込み」から下書きを作れます
（取り込んだだけでは公開されません。精度は保証されません）。


■ 3. 体験用のサンプル組織（デモ）

操作を試したい場合は、サンプル組織「Sample Works株式会社」（組織ID：sample-works）を
使えます。導入担当者が npm run seed で作成します。
ログイン情報と中身は「サンプル組織説明.txt」を参照してください。

・サンプル組織は、本番の組織とは別の組織として作られます。本番データは混ぜないでください。
・作り直すときは npm run seed -- --reset を使います。この操作はサンプル組織だけを削除して
　作り直します（サンプル以外の組織は削除できないようになっています）。
・本番運用を始めたら、サンプル組織のパスワードは公開情報なので、使わない場合は作成しないか、
　導入担当者に削除を依頼してください。


■ 設定チェックリスト

□ オーナーのパスワードを変更した
□ 部署・チームを作った
□ ユーザーを登録し、役割と所属を設定した
□ 承認者の「承認できる範囲」を設定した
□ 文書の種類ごとのルール（承認・定期レビュー・確認依頼）を確認した
□ 機密区分ごとの扱い（オフライン保存・ダウンロード・外部共有）を確認した
□ AI を使うか決めた（使う場合は AI利用時の注意.txt を確認した）
□ バックアップの取り方と保管場所を決めた（バックアップと復元.txt）
□ 最初のマニュアルを公開した
